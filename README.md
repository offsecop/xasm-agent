# xASM Agent

Standalone execution agent for the xASM Platform. The agent enrolls with an
authorized tenant, polls for assigned jobs, executes the installed security
tools, streams progress, and reports structured results back to the platform.

The current distribution loads 124 tool plugins, including network discovery,
Web/API DAST, authenticated browser exploration, cloud and exposure checks,
and evidence-oriented vulnerability probes.

> Use the agent only against assets for which you have explicit authorization.

## Requirements

- Docker Engine with Docker Compose v2
- Outbound access from the agent host to the xASM Platform API
- One enrollment credential set generated by the platform:
  - a dedicated `AGENT_ENROLLMENT_ID` and `AGENT_ENROLLMENT_TOKEN`; or
  - tenant installer `AGENT_CLIENT_ID` and `AGENT_CLIENT_SECRET`
- Enough CPU, memory, and shared memory for scanners and headless Chromium

## Remote installation

1. Clone the repository:

   ```bash
   git clone https://github.com/offsecop/xasm-agent.git
   cd xasm-agent
   ```

2. Create a local environment file:

   ```bash
   cp .env.agent.example .env
   ```

3. Edit `.env` and set:

   - `AGENT_API_URL`, including the `/api` suffix;
   - exactly one enrollment credential pair;
   - a stable and unique `AGENT_INSTALLATION_UID` for this installation;
   - an identifiable `AGENT_NAME` and optional tags.

   The `.env` file and concrete `config*.yaml` files are ignored by Git and by
   the Docker build context.

4. Build and start the agent:

   ```bash
   docker compose -f docker-compose.agent.yml up -d --build
   ```

   Or use the validated helper:

   ```bash
   ./run_docker_agent.sh
   ```

5. Confirm enrollment and tool registration:

   ```bash
   docker compose -f docker-compose.agent.yml logs -f xasm-agent
   ```

   The log should show successful enrollment, heartbeat delivery, and the
   registered tool inventory. The agent should then appear online in the xASM
   Platform operations interface.

## Enrollment options

### Dedicated agent enrollment

Use the one-time credentials generated when an operator creates a specific
agent in the platform:

```dotenv
AGENT_ENROLLMENT_ID=...
AGENT_ENROLLMENT_TOKEN=...
AGENT_CLIENT_ID=
AGENT_CLIENT_SECRET=
```

### Tenant installer enrollment

Use tenant installer credentials when the remote host is allowed to create or
reuse its per-installation agent identity:

```dotenv
AGENT_ENROLLMENT_ID=
AGENT_ENROLLMENT_TOKEN=
AGENT_CLIENT_ID=...
AGENT_CLIENT_SECRET=...
```

Do not commit either credential pair. Each concurrently running agent must use
a different `AGENT_INSTALLATION_UID`. The Compose stack persists the generated
identity in the `xasm-agent-state` volume so container recreation does not
produce duplicate agent records.

## Updating an installation

```bash
git pull --ff-only origin main
docker compose -f docker-compose.agent.yml up -d --build
```

To stop the agent without deleting its persisted installation identity:

```bash
docker compose -f docker-compose.agent.yml down
```

Do not add `--volumes` unless you intentionally want to discard that identity.

## Native development

Docker is recommended because the image installs the external scanners and
Chromium dependencies. For Python-only development:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp config.yaml.example config.yaml
python main_rest.py
```

The native configuration must contain valid enrollment credentials or the
equivalent environment variables.

## Architecture

The agent uses REST polling with a push-notification backstop:

1. enroll with the platform and obtain a per-instance API key;
2. register the locally loaded tools;
3. send periodic heartbeats and poll for authorized jobs;
4. claim and execute jobs with bounded concurrency and timeouts;
5. stream progress, findings, and completion state to the platform.

Key files:

- `main_rest.py` — process entry point and configuration loading
- `agent_core_rest.py` — enrollment, polling, job execution, and reporting
- `plugin_interface.py` — tool plugin contract
- `plugin_loader.py` — tool discovery and parameter normalization
- `tools/` — built-in tool implementations
- `config.yaml.example` — native-development configuration template
- `config.docker.yaml.example` — optional YAML template for advanced deployments
- `docker-compose.agent.yml` — recommended standalone remote deployment

## Custom tools

Create a Python module under `plugins/` and implement a concrete `ToolPlugin`:

```python
from plugin_interface import ToolPlugin


class ExampleTool(ToolPlugin):
    @property
    def name(self):
        return "custom:example"

    @property
    def description(self):
        return "Example custom tool"

    @property
    def schema(self):
        return {
            "type": "object",
            "properties": {"target": {"type": "string"}},
            "required": ["target"],
        }

    async def execute(self, parameters):
        return {"target": parameters["target"], "status": "ok"}
```

Rebuild the image after adding or changing a plugin. The agent registers the
loaded plugin inventory with the platform when it starts.

## Operational checks

```bash
# Container status
docker compose -f docker-compose.agent.yml ps

# Recent logs
docker compose -f docker-compose.agent.yml logs --tail=200 xasm-agent

# Validate the resolved Compose model
docker compose -f docker-compose.agent.yml config --quiet
```

If enrollment fails, first verify the exact API URL, tenant, credential pair,
host clock, DNS, and TLS trust from the remote agent host.
